## Локальная проверка после распаковки

Требуется Python 3.9+ со стандартными `sqlite3`, `hashlib` и возможностью открыть локальный порт. Для интерфейса нужен современный браузер. Пакеты pip/npm и сетевое скачивание зависимостей не требуются. Проверено на Python 3.9.6 и встроенном браузере Codex; это не обещание совместимости со всеми устройствами.

Откройте терминал в распакованной папке `pulse`:

```sh
python3 server.py
```

Дождитесь строки `Пульс: http://127.0.0.1:8000`, затем откройте этот адрес. Сервер должен продолжать работать в терминале. Закрытие терминала или Ctrl+C останавливает сайт. `ERR_CONNECTION_REFUSED` обычно означает, что процесс не запущен. Если порт занят: `python3 server.py --port 8080` и адрес с портом 8080.

На macOS можно дважды нажать `Запустить.command` в Finder. Если после распаковки потерялся исполняемый флаг, используйте команду Python выше. Не нужно отключать системные механизмы защиты.

```sh
python3 -m unittest discover -s tests -v
```

Тесты используют временные базы и свободные порты. Текущую демонстрационную базу они не очищают. В ограниченной среде им может понадобиться разрешение на локальные сокеты.

Строгая проверка ресурсов: `python3 scripts/check_resources.py`. В среде ассистента доступен только Python 3.9.6; фактической проверки на 3.14 не было. При наличии Python 3.14 повторите `python3.14 scripts/check_resources.py`. Найденные незакрытые соединения тестов исправлены, а ошибка настройки серверного соединения теперь тоже гарантированно его закрывает. Интерфейс, схема БД и сценарии относительно v2 не менялись. Новый прогон и ограничения описаны в `final-check.md`; прежние результаты v2 — в `release-notes.md`.

## Настройки окружения

`.env.example` — справочник, не автоматически читаемый файл. Значения задаются в окружении процесса, в настройках хостинга или через `export` оболочки.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Адрес прослушивания; за локальным прокси оставляйте loopback |
| `PORT` | `8000` | Порт; можно переопределить `--port` |
| `PULSE_DB` | `data/pulse.sqlite3` относительно папки `server.py` | Файл SQLite. Для размещения нужен абсолютный путь на постоянном диске |
| `COOKIE_SECURE` | `0` | `1` добавляет флаг Secure к сессионной cookie; включать при внешнем HTTPS |
| `TRUSTED_PROXY_IPS` | пусто | Точные IP единственного доверенного обратного прокси, через запятую. Без настройки X-Forwarded-For игнорируется |

Пример локального запуска с явным постоянным файлом из папки проекта:

```sh
export PULSE_DB="$PWD/data/pulse.sqlite3"
python3 server.py --host 127.0.0.1 --port 8000
```

Для внешнего размещения задайте `PULSE_DB` вне каталога заменяемого кода, на диске выбранного хостинга. Процессу нужны права чтения и записи в сам файл и его каталог — SQLite создаёт рядом `-wal` и `-shm`. Не кладите эти файлы в публичную папку. Не размещайте БД на сетевом диске с непроверенными блокировками; текущая конфигурация рассчитана на один экземпляр приложения.

## Резервная копия и восстановление

Команды ниже выполняются из папки проекта. Если выбран нестандартный `PULSE_DB`, используйте то же окружение или передайте `--source /абсолютный/путь/pulse.sqlite3` команде backup.

```sh
python3 scripts/database.py backup backups/before-update.sqlite3
```

Сервер можно не останавливать: используется SQLite backup API, который учитывает записи в WAL. Не копируйте только файл `.sqlite3` вручную во время работы. Файл назначения должен быть новым: скрипт откажется его перезаписывать. Для следующей копии выберите новое имя.

Копия содержит пользователей и сессии. Храните её приватно, с ограниченными правами, отдельно от кода и хотя бы одну — отдельно от сервера. В исходный архив и описание для жюри её включать нельзя. Автоматического расписания копий и их удаления в проекте нет — это настройка капитана на выбранной платформе.

Чтобы восстановить:

1. Остановите сервер и убедитесь, что не запущен второй процесс с той же БД.
2. Создайте восстановленный файл по новому пути:

```sh
python3 scripts/database.py restore backups/before-update.sqlite3 data/restored.sqlite3
export PULSE_DB="$PWD/data/restored.sqlite3"
python3 server.py
```

3. Войдите обоими студентами и проверьте заявки. Старые сессии при восстановлении сброшены; потребуется войти заново. Исходная БД и резервная копия не перезаписываются.
4. После проверки сохраните новый `PULSE_DB` в постоянной конфигурации запуска.

Backup и restore проверены автоматическими тестами, включая открытую WAL-базу, целостность, сохранение заявок, сброс сессий и отказ перезаписывать существующие файлы.

## Обновление без потери данных

1. Сделайте backup и сохраните прежний архив кода.
2. Остановите процесс приложения.
3. Замените код, оставив постоянный файл БД и настройки окружения отдельно.
4. Запустите новую версию с тем же абсолютным `PULSE_DB`.
5. Проверьте `/healthz`, два входа, прежнюю заявку и создание новой.

Повторный seed не перезаписывает существующие данные. В этой доработке схема БД не изменилась; универсальной системы миграций для будущих изменений пока нет. Откат кода к более ранней версии не гарантируется после будущих миграций без отдельной проверки.

## Требования к самостоятельному размещению

Выберите платформу с долгоживущим Python-процессом и постоянным локальным хранилищем. Статический хостинг или эфемерный файловый диск для этого проекта не подходят.

- Перед приложением нужен обратный прокси с HTTPS и действительным сертификатом. HTTP внешнего сайта должен переводиться на HTTPS. Для внешнего HTTPS установите `COOKIE_SECURE=1`.
- Сохраните исходный Host: сервер сравнивает его с Origin. Прокси не должен подменять Host на внутреннее имя, иначе отправка форм будет отклоняться.
- Не открывайте внутренний Python-порт в интернет. Ограничьте доступ к нему прокси, настройте лимиты размера запросов, таймауты и ограничение частоты на внешнем периметре.
- Для раздельного ограничения входов по IP настройте `TRUSTED_PROXY_IPS` адресом **реального сетевого соседа** приложения. Прокси должен **перезаписывать** X-Forwarded-For единственным IP посетителя, а не дополнять полученный от посетителя заголовок. Списки IP и цепочки нескольких прокси этой реализацией не разбираются. Не задавайте доверие всем адресам. Если настройка неизвестна, оставьте переменную пустой: это безопаснее, но все посетители за прокси разделят один IP-лимит.
- Права на каталог БД и резервные копии выдайте только пользователю приложения. Настройте перезапуск процесса после сбоя/перезагрузки, приватные резервные копии, мониторинг `/healthz` и свободного места.
- `/healthz` проверяет доступ к таблице пользователей и возвращает только `{"status":"ok"}`. Он не раскрывает имена, заявки, конфигурацию и не заменяет проверку записи через создание заявки.
- Не направляйте веб-сервер на корень проекта как на каталог статических файлов. Только приложение должно обрабатывать запросы. Исходники, `.env`, БД и docs не должны стать доступны через конфигурацию внешнего веб-сервера.

Сервер стандартной библиотеки оставлен ради простого конкурсного прототипа. Его не следует открывать напрямую; полномасштабный production-сервер, распределённая БД, нагрузочное тестирование и защита от отказа в обслуживании не реализованы. Таймаут сокета ограничен 15 секундами, но это не полноценная защита от перегрузки. После выбора платформы её пригодность нужно оценить отдельно.

Dockerfile — дополнительная заготовка:

```sh
docker build -t pulse-dean .
docker run --rm -p 127.0.0.1:8000:8000 -v pulse-data:/app/data pulse-dean
```

Данные должны жить в именованном томе. `COOKIE_SECURE`, Host, сеть прокси и права на том настройте для выбранного окружения. Docker в этой сессии **не запускался**; приведённые команды не выдаются за проверенное развёртывание.

## Приёмка после размещения

Проверить нужно именно внешнюю HTTPS-ссылку, а не localhost:

1. Открыть сайт из России без VPN и на реальном телефоне от 360 px. Проверить все разделы и отсутствие перекрытия нижним меню.
2. Проверить оба аккаунта, выход и повторный вход. Создать заявку Алисы, затем убедиться, что Марк её не видит.
3. В инструментах браузера проверить HttpOnly, SameSite=Strict и Secure у cookie, отсутствие ошибок смешанного HTTP/HTTPS и сторонних запросов.
4. Отправить формы: Origin должен проходить через прокси; ошибка 403 требует проверки Host и конфигурации прокси.
5. Попробовать чужой `/api/students/1` из Марка и `/api/requests/ID_АЛИСЫ`, а также файл этой заявки: ожидается 404. Без сессии — 401.
6. Убедиться, что `/server.py`, `/.env`, `/data/pulse.sqlite3`, `/data/pulse.sqlite3-wal`, `/scripts/database.py` и `/.git/config` не доступны. Ожидается 404, без показа файлов.
7. Перезапустить приложение и проверить сохранение заявки. Отдельно сделать backup и пробное восстановление в новую БД.
8. Проверить поведение лимита входов за реальным прокси и корректность доверенного IP. Не проводите такой тест одновременно с показом жюри: на пять минут можно заблокировать демовход.
9. Настроить контроль доступности и сохранение данных до результатов. По переданным материалам — до 28 ноября 2026 года; актуальность дат и правил перепроверьте в кабинете организаторов.
