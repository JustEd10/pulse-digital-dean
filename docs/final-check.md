# Финальная техническая проверка Пульса

7 ноября 2026 года. Доработка по принятому пользователем плану `Друг 2.docx`. Хостинг, публикация и отправка остаются задачами капитана. Эта запись отделяет новый прогон от прежних результатов v2 в `release-notes.md`.

## Изменения относительно v2

В семи местах тестов `with sqlite3.connect(...)` заменён на сочетание `contextlib.closing` и транзакционного контекста. Контекст SQLite сам по себе делает commit/rollback, но не закрывает соединение. Теперь прежние транзакции сохранены, а закрытие выполняется явно. Источник незакрытых соединений найден в четырёх местах `test_app.py` и трёх местах `test_database.py`. Backup-скрипт уже закрывал оба соединения и не требовал изменения.

В серверном `connect()` настройка `row_factory` и `PRAGMA foreign_keys` перенесена внутрь существующего try/finally. Соединение закрывается и при ошибке до входа в контекст. Успешные ответы, данные, схема БД и интерфейс не менялись.

Добавлен один регрессионный тест ошибки первоначальной настройки: всего 15 тестов. Добавлен `scripts/check_resources.py`, который запускает тот же набор со строгими ResourceWarning и проверяет фактическую закрытость соединений после каждого теста. Он инструментирует только процесс тестов; дочерние процессы наследуют строгие предупреждения, но их соединения перехватчиком не отслеживаются. Серверный helper и оба соединения backup-скрипта дополнительно просмотрены по коду.

Проверка не подменяет тестирование на другой версии Python. Контрольный запуск с намеренно оставленным открытым соединением завершился ожидаемым отказом — проверка утечку обнаруживает.

## Доступный Python и предупреждения

Доступен Python 3.9.6. Python 3.14 не найден в PATH и стандартных проверенных каталогах установки. Он не устанавливался. Сообщение о предупреждениях на 3.14 получено из переданного документа капитана; воспроизводить его на этой версии здесь было невозможно.

Прогон рабочей папки: 15/15 тестов успешно, 5,886 секунды, проверка закрытия соединений не обнаружила утечек. ResourceWarning в этом запуске не наблюдались. Это результат Python 3.9.6, а не утверждение об успешном запуске на Python 3.14.

Команда:

```sh
python3 scripts/check_resources.py
```

Капитану с доступным Python 3.14 повторить:

```sh
python3.14 scripts/check_resources.py
```

## Новый прогон из чистой копии

Код распакован в новую временную папку. Выполнен `python3 scripts/check_resources.py`: **15/15 успешно**, 5,895 секунды на Python 3.9.6; открытых SQLite-соединений после тестов не найдено, ResourceWarning не наблюдались. Контрольная проверка намеренной утечки выполнена отдельно и ожидаемо её обнаружила.

Из этой же копии фактически запущен сервер с автоматически создаваемой базой по умолчанию. Оба демоаккаунта вошли. Создана заявка, чтение другим студентом отклонено, после обычного перезапуска с той же БД заявка сохранилась. Выполнены CLI-команды `backup backups/smoke.sqlite3` и `restore backups/smoke.sqlite3 data/restored.sqlite3`; сервер повторно запущен на восстановленной базе, заявка сохранилась. Сценарий запущен со строгими ResourceWarning. Это не Docker и не внешний хостинг.

## Новый браузерный прогон

Проверяется именно сервер чистой распакованной финальной копии, а не ранее оставленная вкладка v2. Встроенный браузер, эмуляция **360 × 800 px**. Повторно пройдены вход Алисы, пять разделов нижнего меню, расписание с семью днями, создание справки о стипендии в двух экземплярах, видимый статус «Сохранена в прототипе», reload и переход к заявке с главной. Ширина документа у входа и пяти основных разделов равна 360 px. Форма и диалог открываются, статус виден, нижняя навигация не перекрывает действие создания.

Повторно проверены выход Алисы, вход Марка, его отдельные дисциплины и профиль, отсутствие новой заявки Алисы в его сохранённых заявках и выход Марка. Профиль также не имеет горизонтального переполнения на 360 px. В конце прогона журнал браузера не содержал ошибок или предупреждений. Новые снимки находятся в `screenshots/final/`: главная, созданная справка и профиль второго студента.

Предыдущие результаты v2 на 390/768/1440 px, проверка сети и полный набор клавиатурных проверок сохранены как история и не выдаются за новые проверки. В новом прогоне Escape закрыл диалог; остальные старые клавиатурные проверки не повторялись. Интерфейс не изменялся.

## Проверка комплекта

Итоговая передача — `artifacts/pulse-handoff-final.zip`, рядом `.zip.sha256`. Пакет собирается скриптом по разрешённому списку. Сверяются CRC ZIP, состав, относительные ссылки документации и байты кода с проверенной чистой копией. После запуска изменены только документация и новые снимки, а не проверенный код. Предыдущие архивы сохранены. В архив не входят БД, резервные копии, `.env`, кэши, входные Word-документы и временные файлы.

Рабочая БД пользователя не использовалась. Тестовые локальные серверы остановлены после проверки.

## Комплект и границы проверки

Комплект включает исходники, README, инструкцию капитану, два демоаккаунта, черновик для жюри, журнал реальных заданий ИИ, снимки, матрицу требований, сценарий будущей проверки с однокурсниками и сценарий необязательного видео. Поля команды, капитана и внешних ссылок в черновике явно оставлены для заполнения человеком. Точная модель не установлена; исследования и видео не выдумывались.

Ограничения продукта прежние: заявки сохраняются только в демонстрации, готовый образец не имеет юридической силы, реальных интеграций и настоящих персональных данных нет. Docker, физические телефоны, разные браузеры, внешний HTTPS/прокси, доступ из России, нагрузка и независимый аудит не проверены в этой среде.

После размещения капитану выполнить приёмку из `captain-guide.md`: два аккаунта и чужие ID, формы/Origin/Host, Secure cookie, постоянная БД после перезапуска, закрытые служебные файлы, backup/restore и доступ из России без VPN. Повторить ресурсы на Python 3.14, оформить итоговый PDF/документ и заполнить ссылки перед отправкой. Ничего не публиковалось.
