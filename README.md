Рабочий локальный конкурсный концепт личного кабинета студента: вход, профиль, расписание, успеваемость, заявки и уведомления. Все студенты, преподаватели, оценки и документы вымышлены. Это не официальный сервис университета.

**Капитану:** начните с [инструкции по передаче и размещению](docs/captain-guide.md). [Описание для жюри](docs/jury-draft.md), [финальная проверка и изменения относительно v2](docs/final-check.md), [история v2](docs/release-notes.md). Публичное размещение выполняет капитан самостоятельно.

## Запуск

Нужен Python 3.9 или новее со стандартными модулями SQLite и hashlib. Установка пакетов, Node.js, npm и внешние сервисы не нужны.

```sh
python3 server.py
```

Откройте http://127.0.0.1:8000. База `data/pulse.sqlite3` создаётся при первом запуске; последующие запуски сохраняют заявки, прочитанность уведомлений и отметки дел. Остановка — Ctrl+C. Другой порт: `python3 server.py --port 8080`.

Для проверки на своём телефоне в одной доверенной Wi-Fi сети: `python3 server.py --host 0.0.0.0`, затем откройте `http://ЛОКАЛЬНЫЙ_IP_КОМПЬЮТЕРА:8000`. Это HTTP для локальной демонстрации; используйте только тестовые данные.

На экране входа можно нажать кнопку студента. Пароли намеренно доступны для демонстрации. Не используйте их в других сервисах. В базе хранятся только отдельные соли и PBKDF2-HMAC-SHA256 хеши, 600 000 итераций. Исходные хеши двух вымышленных аккаунтов зафиксированы в серверном seed.

Смена демонстрационного пароля: `python3 scripts/reset_password.py`. Скрипт запросит новый пароль без отображения, обновит хеш и завершит все сессии пользователя. После смены нужно вручную обновить демонстрационную кнопку в `public/app.js` и инструкции жюри. Для полностью новой демонстрационной базы остановите сервер и задайте новый путь через `PULSE_DB`; существующую базу можно оставить как резервную копию.

1. Войти как Алиса. Посмотреть главный экран, учебный день и срочные дела.
2. В расписании переключить день и неделю. Найти перенос в аудиторию 412.
3. Открыть успеваемость и даты демонстрационной сессии.

## Технологии и безопасность

Сервер — стандартная библиотека Python, хранилище — SQLite с WAL. Интерфейс — HTML, CSS и JavaScript без зависимостей. Стек выбран для воспроизводимого запуска и понятной проверки прав, без установки Node.js, которого нет в текущей среде. Расписание и оценки — серверные демонстрационные наборы; пользователи, заявки, сессии, дела и уведомления — SQLite. Время и неделя вычисляются по Москве.

Сессия — случайный токен на 12 часов в HttpOnly / SameSite=Strict cookie; в БД хранится SHA-256 токена. Выход удаляет серверную сессию. Личные API берут пользователя из сессии. SQL-запросы параметризованы, выборка заявок дополнительно ограничена владельцем. Подстановка чужого `user_id` в форму не меняет владельца. Изменения требуют CSRF-токен, проверяется Origin. Ограничение входа — 10 неудачных попыток за 5 минут по IP или логину. Интерфейс экранирует пользовательский текст; CSP запрещает сторонние скрипты, встроенные скрипты и встраивание страницы.

Переменные: `HOST`, `PORT`, `PULSE_DB`, `COOKIE_SECURE`, `TRUSTED_PROXY_IPS`. Образец в `.env.example`; файл автоматически не загружается. Пример: `PORT=8080 python3 server.py`. Для HTTPS задайте `COOKIE_SECURE=1`; прокси должен сохранять исходный Host. Доверие к IP прокси задаётся отдельно, с обязательной перезаписью X-Forwarded-For одним адресом посетителя. Подробности в инструкции капитану. Секретные ключи и внешние интеграции не требуются. Базу и `.env` нельзя включать в исходный архив или репозиторий.

## Резервное копирование

```sh
python3 scripts/database.py backup backups/before-update.sqlite3
python3 scripts/database.py restore backups/before-update.sqlite3 data/restored.sqlite3
```

Файлы назначения должны быть новыми. Backup учитывает WAL работающей базы. Восстановление не перезаписывает исходник и сбрасывает сессии. Перед переключением базы остановите сервер, затем запустите его с новым `PULSE_DB`. Подробный порядок и сохранение данных между обновлениями — в инструкции капитану. Резервные копии приватны и не входят в исходный архив.

## Проверка

```sh
python3 -m unittest discover -s tests -v
```

15 тестов запускают настоящие HTTP-серверы на свободных портах и временные БД. Проверяют анонимный доступ, оба аккаунта, владение данными, CSRF и Origin, валидацию, сохранение, загрузку образца, выход, хеши, резервные копии, восстановление, Secure cookie, доверие к прокси и закрытие соединения при ошибке его настройки. Им нужен доступ к локальным сокетам.

Для того же набора со строгими ResourceWarning и проверкой закрытия SQLite-соединений:

```sh
python3 scripts/check_resources.py
```

Перехватчик отслеживает соединения в процессе тестов; дочерние серверы и CLI наследуют строгий фильтр предупреждений, но их соединения им не отслеживаются. Доступен Python 3.9.6. На Python 3.14 капитану нужно повторить `python3.14 scripts/check_resources.py`: эта версия в текущей среде недоступна. Результаты и ограничения — в `docs/final-check.md` и `docs/requirements.md`.

## Подготовка размещения

Приложение пока не опубликовано. Dockerfile подготовлен, но Docker в этой сессии не запускался:

```sh
docker build -t pulse-dean .
docker run --rm -p 127.0.0.1:8000:8000 -v pulse-data:/app/data pulse-dean
```

Для конкурса нужен сервер с постоянным диском и HTTPS, доступный из России. Проверить доступность из реальной российской сети и хранить сервис до объявления результатов. Python `http.server` здесь служит прототипу; перед промышленной эксплуатацией нужны полноценный сервер приложения, резервное копирование, аудит и нагрузочные проверки. Docker-образ и доступность конкретного хостинга ещё не проверены.

## Дополнительные проверки интерфейсной логики

При наличии Node 18+ можно выполнить `node tests/test_motion.js`. Это 11 изолированных проверок реального JavaScript с моделью DOM/таймеров, без браузера и сетевых запросов. Они не доказывают плавность CSS или работу системного reduced motion. Node нужен только для этих дополнительных тестов, не для запуска самого кабинета; сторонние пакеты не требуются. В этой среде проверки выполнены через встроенный Node runtime, поскольку команды `node` в PATH нет.
